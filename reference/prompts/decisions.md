### File 2 — `{{outputFindingMap}}`

A JSON object, this exact shape:

```json
{
  "defaults": { "<as-built path id>": ["<decision id>", "…"] },
  "findings": { "<finding id>": ["<decision id>", "…"], "<finding id>": ["OPEN", "<reason>"] },
  "observed": ["<one-line note>", "…"]
}
```

- `defaults`: for each as-built path that a target path replaces, the decision IDs that apply to every finding on that path unless a specific finding overrides it (for example, "this whole job's queue was removed, decision D-03, closes every finding on it").
- `findings`: for every live finding in `{{findingsFile}}` not already covered by a default, its own entry: either the decision ID(s) that close it, or `["OPEN", "<one-sentence reason it stays open>"]`. A finding left open needs a real reason (deferred to a later phase, needs a call only the owner can make, or genuinely out of scope for this redesign) — "forgot" is not a reason; if you truly cannot map it, that is a wall, and you say so instead of inventing a reason.
- `observed`: the same list as DECISIONS.md's "Observed during step 2" section, as plain strings.

**Definition of done for this file: zero unmapped live S1 or S2 findings.** Walk `{{findingsFile}}` finding by finding (skip `DROPPED` rows) and confirm each one resolves through `defaults` or `findings` to a decision or an explicit `OPEN` with a reason. Do this walk before you finish, not as an afterthought; `synthesize-target` will throw on anything you missed.

Return: the decision count, the OWNER-DECISION count still needing an answer, the OPEN finding count with reasons, and confirmation that every live S1 and S2 finding is mapped (or the exact ones that are not, if you hit a real wall on one).
